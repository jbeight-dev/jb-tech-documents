    ContextForge

    작성일: 2026-10-30

    MCP, A2A, REST/gRPC API를 중앙화된 거버넌스, 디스커버리, 관측성(observability)과 함께 연합(federate)하는 오픈소스 레지스트리이자 프록시입니다. 에이전트와 도구 호출을 최적화하며, 플러그인을 지원합니다.

    ContextForge는 도구, 에이전트, API를 AI 클라이언트를 위한 하나의 깔끔한 엔드포인트로 연합하는 오픈소스 레지스트리이자 프록시입니다. AI 인프라 전반에 중앙화된 거버넌스, 디스커버리, 관측성을 제공합니다.

    • Tools Gateway — MCP, REST, gRPC-MCP 변환, TOON 압축
    • Agent Gateway — A2A 프로토콜, OpenAI 호환 및 Anthropic 에이전트 라우팅
    • API Gateway — REST 서비스를 위한 속도 제한(rate limiting), 인증, 재시도, 리버스 프록시
    • 플러그인 확장성 — 추가 전송 방식, 프로토콜, 통합을 위한 40개 이상의 플러그인
    • 관측성 — Phoenix, Jaeger, Zipkin 및 기타 OTLP 백엔드를 이용한 OpenTelemetry 트레이싱

    ContextForge는 MCP 사양을 완전히 준수하는 MCP 서버로 동작하며, PyPI나 Docker로 배포할 수 있고, Redis 기반 연합과 캐싱으로 Kubernetes의 멀티 클러스터 환경까지 확장됩니다.

    개요와 목표

    ContextForge는 모든 Model Context Protocol(MCP) 서버, A2A 서버, REST/gRPC API를 연합하고 중앙화된 거버넌스, 디스커버리, 관측성을 제공하는 오픈소스 레지스트리이자 프록시입니다. 에이전트와 도구 호출을 최적화하며, 플러그인을 지원합니다. 자세한 내용은 프로젝트 로드맵을 참고하세요.

    현재 지원하는 기능은 다음과 같습니다.

    • 여러 MCP 및 REST 서비스에 걸친 연합
    • 외부 AI 에이전트(OpenAI, Anthropic, 사용자 정의)를 위한 A2A(Agent-to-Agent) 통합
    • 리플렉션 기반 자동 서비스 디스커버리를 통한 gRPC-MCP 변환
    • 레거시 API를 MCP 호환 도구와 서버로 가상화
    • HTTP, JSON-RPC, WebSocket, SSE(keepalive 설정 가능), Streamable HTTP를 통한 전송. 서버 측에서는 stdio 전송도 사용 가능
    • 실시간 관리, 설정, 로그 모니터링을 위한 Admin UI(에어갭 배포 지원)
    • 별도 컨테이너에서 실행되는, 새롭게 디자인되어 더 사용하기 쉬운 웹 UI
    • 사용자 범위 OAuth 토큰과 무조건적인 X-Upstream-Authorization 헤더 지원을 갖춘 내장 인증, 재시도, 속도 제한
    • Phoenix, Jaeger, Zipkin 및 기타 OTLP 백엔드를 이용한 OpenTelemetry 관측성
    • Docker 또는 PyPI를 통한 확장 가능한 배포, Redis 기반 캐싱, 멀티 클러스터 연합

    예정된 기능 목록은 ContextForge 로드맵을 확인하세요.

    • 다양한 백엔드 지원: Phoenix(LLM 중심), Jaeger, Zipkin, Tempo, DataDog, New Relic
    • 연합된 게이트웨이와 서비스 전반의 분산 트레이싱

    • LLM 전용 메트릭: 토큰 사용량, 비용, 모델 성능
    • 비활성화 시 오버헤드 없음, 우아한 성능 저하(graceful degradation)

    Phoenix, Jaeger 및 기타 백엔드 설정 가이드는 관측성 문서를 참고하세요.

    빠른 시작 - PyPI

    ContextForge는 PyPI에 mcp-contextforge-gateway로 게시되어 있습니다.

    ⚠️ JWT_SECRET_KEY와 AUTH_ENCRYPTION_SECRET은 로컬 개발을 포함한 모든 환경에서 필수입니다. 이 값들이 없으면 게이트웨이가 시작되지 않습니다. 처음 실행하기 전에 python3 -m mcpgateway.scripts.init_secrets로 실제 시크릿을 생성하세요.

    TLDR — uv를 사용하는 단일 명령:

    # 1️⃣  Generate secure secrets (creates .env.secrets)
python3 -m mcpgateway.scripts.init_secrets

# 2️⃣  Export the generated values
export JWT_SECRET_KEY="$(grep '^JWT_SECRET_KEY=' .env.secrets | cut -d= -f2)"
export AUTH_ENCRYPTION_SECRET="$(grep '^AUTH_ENCRYPTION_SECRET=' .env.secrets | cut -d= -f2)"

# 3️⃣  Start the gateway
JWT_SECRET_KEY="$JWT_SECRET_KEY" \
AUTH_ENCRYPTION_SECRET="$AUTH_ENCRYPTION_SECRET" \
MCPGATEWAY_UI_ENABLED=true \
MCPGATEWAY_ADMIN_API_ENABLED=true \
PLATFORM_ADMIN_EMAIL=admin@example.com \
uvx --from mcp-contextforge-gateway mcpgateway --host 0.0.0.0 --port 4444
    📋 사전 요구 사항
    • Python ≥ 3.11
    • curl + jq - 마지막 스모크 테스트 단계에서만 필요

    1 - 설치 및 실행(복사해서 붙여넣기 쉬운 버전)

    # 1️⃣  Create an isolated env and install from PyPI
mkdir mcpgateway && cd mcpgateway
python3 -m venv .venv && source .venv/bin/activate
pip install --upgrade pip
pip install mcp-contextforge-gateway

# 2️⃣  Download .env.example and generate real secrets
curl -O https://raw.githubusercontent.com/IBM/mcp-context-forge/main/.env.example
cp .env.example .env

# Generate cryptographically secure secrets into .env.secrets
python3 -m mcpgateway.scripts.init_secrets

# Patch the generated secrets into .env (replaces __REPLACE_ME__ placeholders)
python3 -m mcpgateway.scripts.init_secrets --patch-env .env

# 3️⃣  Start the gateway
mcpgateway --host 0.0.0.0 --port 4444 &

# 4️⃣  Generate a bearer token and smoke-test
export JWT_SECRET_KEY=$(grep '^JWT_SECRET_KEY=' .env | cut -d= -f2)
export MCPGATEWAY_BEARER_TOKEN=$(python3 -m mcpgateway.utils.create_jwt_token \
    --username admin@example.com --exp 10080 --secret "$JWT_SECRET_KEY")

curl -s -H "Authorization: Bearer $MCPGATEWAY_BEARER_TOKEN" \
     http://127.0.0.1:4444/version | jq

    추가 설정

    .env.example을 .env로 복사하고 원하는 설정을 조정하세요(또는 환경 변수로 사용하세요).

    🚀 엔드 투 엔드 데모(로컬 MCP 서버 등록) 
    # 1️⃣  Spin up the sample MCP time server using mcpgateway.translate & docker (replace docker with podman if needed)
python3 -m mcpgateway.translate \
     --stdio "docker run --rm -i ghcr.io/ibm/fast-time-server:latest -transport=stdio" \
     --expose-sse \
     --port 8003

# Or using the official mcp-server-git using uvx:
pip install uv # to install uvx, if not already installed
python3 -m mcpgateway.translate --stdio "uvx mcp-server-git" --expose-sse --port 9000

# NEW: Expose via multiple protocols simultaneously!
python3 -m mcpgateway.translate \
     --stdio "uvx mcp-server-git" \
     --expose-sse \
     --expose-streamable-http \
     --port 9000
# Now accessible via both /sse (SSE) and /mcp (streamable HTTP) endpoints

# 2️⃣  Register it with the gateway
curl -s -X POST -H "Authorization: Bearer $MCPGATEWAY_BEARER_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"name":"fast_time","url":"http://localhost:8003/sse"}' \
     http://localhost:4444/gateways

# 3️⃣  Verify tool catalog
curl -s -H "Authorization: Bearer $MCPGATEWAY_BEARER_TOKEN" http://localhost:4444/tools | jq

# 4️⃣  Create a *virtual server* bundling those tools. Use the ID of tools from the tool catalog (Step #3) and pass them in the associatedTools list.
curl -s -X POST -H "Authorization: Bearer $MCPGATEWAY_BEARER_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"server":{"name":"time_server","description":"Fast time tools","associated_tools":[<ID_OF_TOOLS>]}}' \
     http://localhost:4444/servers | jq

# Example curl
curl -s -X POST -H "Authorization: Bearer $MCPGATEWAY_BEARER_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"server":{"name":"time_server","description":"Fast time tools","associated_tools":["6018ca46d32a4ac6b4c054c13a1726a2"]}}' \
     http://localhost:4444/servers | jq

# 5️⃣  List servers (should now include the UUID of the newly created virtual server)
curl -s -H "Authorization: Bearer $MCPGATEWAY_BEARER_TOKEN" http://localhost:4444/servers | jq

# 6️⃣  Client HTTP endpoint. Inspect it interactively with the MCP Inspector CLI (or use any MCP client)
npx -y @modelcontextprotocol/inspector
# Transport Type: Streamable HTTP, URL: http://localhost:4444/servers/UUID_OF_SERVER_1/mcp,  Header Name: "Authorization", Bearer Token

    빠른 시작 - 컨테이너

    GHCR의 공식 OCI 이미지를 Docker 또는 Podman으로 사용합니다.
    참고: 현재 운영 환경에서는 arm64를 지원하지 않습니다. 예를 들어 Apple Silicon 칩(M1, M2 등)을 쓰는 MacOS에서 실행한다면, Rosetta를 사용해 컨테이너를 실행하거나 대신 PyPi로 설치할 수 있습니다.

    🚀 빠른 시작 - Docker Compose

    중요: docker compose up -d는 기본적으로 게이트웨이 이미지를 로컬에서 빌드하지 않습니다 — GHCR에서 미리 빌드된 이미지를 사용합니다. compose 파일에는 대체 수단으로 build: 블록이 있지만, 로컬 빌드에는 CI 파이프라인에서만 생성되는 밀폐형(hermetic) wheel 클로저가 필요합니다. 빌드 중에 cryptography 오류나 의존성 해석 오류가 보인다면 이 경우에 해당하므로, 대신 이미지를 pull하세요(아래 2단계가 이를 자동으로 처리합니다).

    docker compose up -d를 실행하기 전에 실제 시크릿이 들어 있는 .env 파일도 반드시 있어야 합니다. placeholder 값으로는 게이트웨이가 시작되지 않습니다.

    PostgreSQL과 Redis를 포함한 전체 스택을 실행합니다.

    # 1️⃣  Clone the repository
git clone https://github.com/IBM/mcp-context-forge.git
cd mcp-context-forge

# 2️⃣  Set up .env with real secrets AND pull the pre-built images
cp .env.example .env
python3 -m mcpgateway.scripts.init_secrets --patch-env .env
# .env now has strong JWT_SECRET_KEY and AUTH_ENCRYPTION_SECRET

# Pull pre-built images from GHCR (avoids local build entirely)
docker pull ghcr.io/ibm/mcp-context-forge:latest
echo 'IMAGE_LOCAL=ghcr.io/ibm/mcp-context-forge:latest' >> .env

# Build only the nginx image (small, local-only, builds in seconds)
docker compose build nginx

# 3️⃣  Start the full stack
docker compose up -d

# 4️⃣  Check status
docker compose ps

# 5️⃣  View logs
docker compose logs -f gateway

# 6️⃣  Access Admin UI: http://localhost:8080/admin
#     Login: PLATFORM_ADMIN_EMAIL / PLATFORM_ADMIN_PASSWORD (from .env)

# 7️⃣  Generate an API token
export JWT_SECRET_KEY=$(grep '^JWT_SECRET_KEY=' .env | cut -d= -f2)
docker compose exec gateway python3 -m mcpgateway.utils.create_jwt_token \
  --username admin@example.com --exp 10080 --secret "$JWT_SECRET_KEY"

    구성 요소:

    • 🗄️ PostgreSQL - 55개 이상의 테이블을 갖춘 운영 환경용 데이터베이스
    • 🚀 ContextForge - Admin UI를 포함한 모든 기능을 갖춘 게이트웨이
    • 📊 Redis - 고성능 캐싱과 세션 저장소
    • 🔧 관리 도구 - 데이터베이스 관리를 위한 pgAdmin, Redis Insight
    • 🌐 Nginx 프록시 - 포트 8080의 캐싱 리버스 프록시

    HTTPS 활성화(선택 사항):

    # Start with TLS enabled (auto-generates self-signed certs)
make compose-tls

# Access via HTTPS: https://localhost:8443/admin

# Or bring your own certificates:
# Unencrypted key:
mkdir -p certs
cp your-cert.pem certs/cert.pem && cp your-key.pem certs/key.pem
make compose-tls

# Passphrase-protected key:
mkdir -p certs
cp your-cert.pem certs/cert.pem && cp your-encrypted-key.pem certs/key-encrypted.pem
echo "KEY_FILE_PASSWORD=your-passphrase" >> .env
make compose-tls

    선택 사항: 웹 UI

    ContextForge Web UI v0.2.4는 내장 Admin UI와 별개로, 새롭게 디자인되어 더 사용하기 쉬운 인터페이스를 제공합니다.
    자체 컨테이너에서 실행되며 게이트웨이 API에 연결합니다.

    위의 Docker Compose 설정을 마친 뒤, 게이트웨이 체크아웃 디렉터리에서 다음 명령으로 웹 UI를 시작합니다.

    make compose-pull PROFILE="--profile ui"
make compose-up PROFILE="--profile ui"

    http://localhost:3001을 열고 게이트웨이 계정으로 로그인하세요.
    포트를 바꾸려면 .env에서 WEB_UI_PORT를 설정합니다.
    ui 프로필은 게이트웨이와 함께 웹 UI와 전용 Redis 세션 저장소를 시작합니다.

    PROFILE은 Makefile의 기본 프로필을 대체합니다.

    🌐 UAID 게이트웨이 간 라우팅 보안

    UAID 보안 설정

    운영 환경 요구 사항:

    게이트웨이 간 UAID 라우팅에는 명시적인 보안 설정이 필요합니다.

    1. 도메인 허용 목록 설정: 
      UAID_ALLOWED_DOMAINS=["gateway1.example.com", "gateway2.example.com"]
    2. JWT 신뢰 보장:
      • 두 게이트웨이 모두 같은 JWT 발급자를 신뢰해야 합니다
      • 옵션 A: 공유 시크릿(모든 게이트웨이에 같은 JWT_SECRET_KEY)
      • 옵션 B: 연합 SSO(Google, GitHub, Entra ID)
    3. 인증 활성화: 
      AUTH_REQUIRED=true
UAID_FORWARD_AUTH=true

    인증 흐름:

    게이트웨이 간 호출은 Authorization 헤더로 사용자의 bearer 토큰을 전달합니다.
    원격 게이트웨이는 기존 인증 미들웨어로 토큰을 검증하며, RBAC 컨텍스트를 유지합니다.

    보안 기능:

    • ✅ 기본값 fail-closed: 허용 목록이 비어 있으면 모든 게이트웨이 간 라우팅을 차단
    • ✅ Bearer 토큰 전달: 여러 홉에 걸쳐 사용자 인증 유지
    • ✅ 감사 추적: 출발 게이트웨이와 사용자를 헤더로 추적
    • ✅ 명확한 오류 메시지: 잘못된 설정을 시작 시점과 런타임에 포착

    문제 해결:

    • "UAID_ALLOWED_DOMAINS not configured" 오류: .env의 허용 목록에 신뢰하는 도메인을 추가하세요
    • 원격 게이트웨이에서 401/403: 두 게이트웨이가 같은 JWT 발급자를 신뢰하는지 확인하세요
    • "proceeding without authentication token" 경고: 인증 미들웨어가 토큰을 request.state.bearer_token으로 추출하는지 확인하세요

    자세한 보안 아키텍처는 docs/security/uaid-cross-gateway-auth.md를 참고하세요.

    문제 해결

    자주 발생하는 문제와 해결 방법:

    문제빠른 해결
    docker compose up이 cryptography 또는 의존성 해석 오류로 실패로컬 빌드에는 CI가 생성한 wheel 클로저가 필요합니다. docker pull ghcr.io/ibm/mcp-context-forge:latest && echo 'IMAGE_LOCAL=ghcr.io/ibm/mcp-context-forge:latest' >> .env를 실행한 뒤 다시 시도하세요
    docker compose up이 SecurityConfigurationError: jwt_secret_key로 실패.env가 없거나 __REPLACE_ME__ placeholder가 남아 있습니다. cp .env.example .env && python3 -m mcpgateway.scripts.init_secrets --patch-env .env를 실행하세요
    docker compose up 실패 — mcpgateway/nginx-cache pull 접근 거부nginx 이미지는 로컬에서 빌드해야 합니다: docker compose build nginx
    make dev — 포트 8000에 아무것도 없음터미널에서 SecurityConfigurationError를 확인하세요 — make ensure-secrets를 실행한 뒤 다시 시도합니다. WSL2에서는 localhost가 아니라 http://127.0.0.1:8000을 사용하세요
    macOS에서 SQLite "disk I/O error"iCloud와 동기화되는 디렉터리를 피하고 ~/mcp-context-forge/data를 사용하세요
    WSL2에서 포트 4444에 접근할 수 없음Docker Desktop에서 WSL 통합을 설정하세요
    게이트웨이가 즉시 종료됨cp .env.example .env && python3 -m mcpgateway.scripts.init_secrets --patch-env .env를 실행하세요
    ModuleNotFoundErrormake install-dev를 실행하세요

    자세한 문제 해결 가이드는 문제 해결 문서를 참고하세요.
