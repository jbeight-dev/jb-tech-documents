    DataHub 개념

    DataHub의 핵심 개념을 살펴보고 데이터 관리에 DataHub의 기능을 충분히 활용해 보세요.

    일반 개념

    URN(Uniform Resource Name)

    URN(Uniform Resource Name)은 DataHub에서 모든 리소스를 고유하게 정의하기 위해 채택한 URI 체계입니다. 형식은 다음과 같습니다.

    urn:<Namespace>:<Entity Type>:<ID>

    예를 들어 urn:li:dataset:(urn:li:dataPlatform:hive,fct_users_created,PROD), urn:li:corpuser:jdoe 등이 있습니다.

    Policy

    DataHub의 접근 정책(access policy)은 누가 어떤 리소스에 무엇을 할 수 있는지를 정의합니다.

    • 권한 부여: Policies 가이드
    • 개발자 가이드: DataHubPolicy
    • 기능 가이드: DataHub 접근 정책 소개

    Role

    DataHub에서는 Role을 사용해 권한을 관리할 수 있습니다.

    • 권한 부여: DataHub Role 소개
    • 개발자 가이드: DataHubRole

    Access Token(Personal Access Token)

    Personal Access Token(줄여서 PAT)을 사용하면 보안이 중요한 배포 환경에서 사용자가 코드상에서 자신을 대표하고 DataHub의 API를 프로그래밍 방식으로 사용할 수 있습니다. 인증이 활성화된 메타데이터 서비스와 함께 사용하면, PAT는 인가된 사용자만 자동화된 방식으로 작업을 수행할 수 있도록 DataHub에 보호 계층을 하나 더합니다.

    • 인증: DataHub Personal Access Token 소개
    • 개발자 가이드: DataHubAccessToken

    View

    View를 사용하면 DataHub를 탐색할 때 재사용할 필터 조합을 저장하고 공유할 수 있습니다. View는 공개(public) 또는 개인(personal)으로 설정할 수 있습니다.

    • DataHubView

    Deprecation

    Deprecation은 엔티티의 지원 중단(deprecation) 상태를 나타내는 aspect입니다. 일반적으로 Boolean 값으로 표현합니다.

    • 데이터셋의 Deprecation

    Ingestion Source

    Ingestion source는 메타데이터를 추출하는 대상 데이터 시스템을 말합니다. 예를 들어 BigQuery, Looker, Tableau를 비롯한 여러 시스템용 소스가 있습니다.

    • Sources
    • DataHub 통합

    Container

    서로 관련된 데이터 자산을 담는 컨테이너입니다.

    • 개발자 가이드: Container

    Data Platform

    Data Platform은 Dataset, Dashboard, Chart를 비롯해 메타데이터 그래프에 모델링된 모든 종류의 데이터 자산을 담고 있는 시스템이나 도구입니다.

    Dataset

    Dataset은 데이터 모음을 나타냅니다. 일반적으로 데이터베이스(예: BigQuery, Snowflake, Redshift 등)의 Table이나 View, 스트림 처리 환경(Kafka, Pulsar 등)의 Stream, 데이터 레이크 시스템(S3, ADLS 등)의 File이나 Folder 형태로 존재하는 데이터 묶음이 여기에 해당합니다.

    • 개발자 가이드: Dataset

    Chart

    Dataset에서 만든 단일 데이터 시각화입니다. Chart 하나가 여러 Dashboard에 포함될 수 있습니다. Chart에는 태그, 소유자, 링크, 용어집 용어, 설명을 붙일 수 있습니다. Superset이나 Looker의 Chart가 그 예입니다.

    • 개발자 가이드: Chart

    Dashboard

    시각화를 위한 Chart 모음입니다. Dashboard에는 태그, 소유자, 링크, 용어집 용어, 설명을 붙일 수 있습니다. Superset이나 Mode의 Dashboard가 그 예입니다.

    • 개발자 가이드: Dashboard

    Data Job

    데이터 자산을 처리하는 실행 가능한 작업입니다. 여기서 "처리"는 데이터를 소비하거나, 생성하거나, 둘 다 하는 것을 뜻합니다. 오케스트레이션 시스템에서는 "DAG" 안의 개별 "Task"라고 부르기도 합니다. Airflow Task가 그 예입니다.

    • 개발자 가이드: Data Job

    Data Flow

    서로 의존성이 있는 Data Job들로 이루어진 실행 가능한 모음, 즉 DAG입니다. "Pipeline"이라고 부르기도 합니다. Airflow DAG가 그 예입니다.

    • 개발자 가이드: Data Flow

    Glossary Term

    데이터 생태계 안에서 공유하는 어휘입니다.

    • 기능 가이드: Glossary
    • 개발자 가이드: GlossaryTerm

    Glossary Term Group

    Glossary Term Group은 폴더와 비슷합니다. Term뿐 아니라 다른 Term Group도 담을 수 있어 중첩 구조를 만들 수 있습니다.

    • 기능 가이드: Term과 Term Group

    Tag

    Tag는 검색과 탐색을 돕는 비공식적이고 느슨하게 관리되는 레이블입니다. 데이터셋, 데이터셋 스키마, 컨테이너에 추가할 수 있으며, 더 넓은 비즈니스 용어집이나 어휘와 연결하지 않고도 엔티티에 레이블을 붙이거나 분류하는 간편한 방법입니다.

    • 기능 가이드: DataHub Tag 소개
    • 개발자 가이드: Tags

    Domain

    Domain은 관련 자산을 명시적으로 묶을 수 있도록 큐레이션한 최상위 폴더 또는 카테고리입니다.

    • 기능 가이드: DataHub Domain 소개
    • 개발자 가이드: Domain

    Owner

    Owner는 엔티티에 대한 소유권을 가진 사용자나 그룹을 말합니다. 소유권은 데이터셋, 컬럼 또는 다른 엔티티에 지정할 수 있습니다.

    • 시작하기: 데이터셋/컬럼에 Owner 추가하기

    Users(CorpUser)

    CorpUser는 기업 내 개인(또는 계정)의 ID를 나타냅니다.

    • 개발자 가이드: CorpUser

    Groups(CorpGroup)

    CorpGroup은 기업 내 사용자 그룹의 ID를 나타냅니다.

    • 개발자 가이드: CorpGroup

    메타데이터 모델

    Entity

    엔티티는 메타데이터 그래프의 기본 노드입니다. 예를 들어 Dataset이나 CorpUser의 인스턴스가 엔티티입니다.

    • DataHub는 메타데이터를 어떻게 모델링하나요?

    Aspect

    Aspect는 엔티티의 특정 측면을 설명하는 속성 모음입니다. Aspect는 여러 엔티티가 공유할 수 있습니다. 예를 들어 "Ownership"은 소유자가 있는 모든 엔티티에서 재사용하는 aspect입니다.

    • 메타데이터 aspect란?
    • DataHub는 메타데이터를 어떻게 모델링하나요?

    Relationships

    Relationship은 두 엔티티 사이의 이름 있는 엣지를 나타냅니다. Aspect 안의 외래 키 속성과 커스텀 어노테이션(@Relationship)으로 선언합니다.
